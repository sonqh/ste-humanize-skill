# Verification 012 OpenSpec pin

Date: 2026-11-12.

This change fixes two risks of change 011. OpenSpec now runs as version 2.0.0 through `scripts/openspec.sh`. `openspec/config.yaml` names the stock schema `spec-driven`. To roll back, revert the commit of this change.

## Files

- `scripts/openspec.sh`: new. It pins OpenSpec 2.0.0.
- `spec-ctx.toml`: `[gate] openspec = "bash scripts/openspec.sh"`. The gate, `next`, and the CI action read it.
- `openspec/config.yaml`: `schema: spec-driven`. `specctx init --schema` merged one rule item and three operation items. The old apply item went, because the new one says the same and names `specctx-run`. A new archive item says that `openspec` means `bash scripts/openspec.sh`.
- `openspec/schemas/spec-driven-ids/`: removed. Its four templates are now in `openspec/templates/spec-driven-ids/`, with the same bytes.
- `.gitignore`: `init --schema` added `adopt-report.md`.
- `.claude/CLAUDE.md`, `docs/CONTRIBUTING.md`: they name the script. CONTRIBUTING says how to upgrade OpenSpec.
- `tests/test_engine_pin.py`: three tests, one for each scenario of REQ-SKILL-014.

## Findings on the way

- `init --schema` adds an item of spec-ctx again when its text differs. The first edit of the two archive items gave two copies. The items of spec-ctx now stay as they are. A second run of `init --schema` added nothing.
- The `.openspec.yaml` of change 012 named `spec-driven-ids`, because the change came before the schema moved. `openspec status` failed with `Unknown schema 'spec-driven-ids'`, and `next` returned `stop`. The file now names `spec-driven`. Seven archived changes keep the old name. Validate does not read it.
- The `specctx-run` skill names the latest OpenSpec for a project with no `[gate] openspec`. The test skips the skill copies of spec-ctx.
- `scripts/lint.py` found a `synonym-rotation` in `design.md` that the gate passed. This is `sonqh/spec-ctx#40`.
